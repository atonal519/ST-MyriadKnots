# Myriad Knots（千千结）

`ST-MyriadKnots` 是 SillyTavern 的长期记忆扩展，界面中文名为“千千结”。项目仓库：[github.com/atonal519/ST-MyriadKnots](https://github.com/atonal519/ST-MyriadKnots)。

## 当前功能

- 为每个聊天建立稳定身份，并保持聊天、角色卡与 Persona 之间的数据隔离。
- 从同一角色聊天创建分支时，新聊天会继承实际保留楼对应的摘要与人物状态，并沿用这些人物的最新版资料；源聊天后续楼不会带入，复制过程不调用模型。
- 从稳定 AI 楼提取带证据的 FloorMemory；支持历史重建、断点继续、逐楼重算和用户修订摘要。
- 手动历史补齐与完全重构在首楼建立人物状态基础后，后一楼摘要可与前一楼 CSE 同时请求，每路最多一个请求。摘要失败会继续其他楼，CSE 不越过摘要缺口；CSE 失败只暂停本批人物状态分析，其他摘要继续，已保存结果保留。
- 完全重构会删除当前聊天全部千千结记录及前情，包括人物资料、头像、重要人物选择、时间事项、人工修改和旧版本，再以新身份从聊天正文重新建档；普通“删除当前聊天记忆”仍保留前情。两者都保留聊天正文、其他插件数据和全局设置。
- 已保存楼的正文后来发生普通编辑时，用户仍可基于当前正文修订摘要、时间、地点和人物；保存前后若目标再次变化则拒绝迟到写入。
- 摘要时间优先读取标准 QQJ/SDC/myknots 时间戳；缺少标准时间戳时，可从正文原文中的成对标签补充完整时间参考。补充标签默认留空，可在设置中显式填写 `Ti` 或其他自定义标签。该设置只影响后续摘要提取，不改变正文清洗，也不会自动重做旧摘要。
- 以正文为最高事实源，通过 CSE 维护人物核心、适应性与情境状态；坏条目不会误清空旧分类，合法证据也不会被同批坏引用连坐。
- 可选时间推演默认关闭，直接读取当前选中、清洗后的 AI 正文，使用摘要 API 追踪身体状态、周期与约定期限，摘要与 CSE 可为空。历史观察满足时间条件时可同次登记并推算到当前，未知或倒退时间不强算；推测独立保存，不改写旧 CSE，也不是已发生的新事实。
- “千结 → 近期事项”可折叠查看、编辑和整理当前追踪清单；“补查历史”先显示待查楼数、预计批次和 API 调用量，确认后分批读取正文。楼内“本轮时间参考”展示该楼原回执真正入选的参考，追踪总数不等于本轮注入数量。
- 千事随新楼摘要在同一次请求中提取事件、事项进展和明确先后关系，并参与普通召回；旧摘要不会自动补写千事。插件已提供手动历史补齐接口，界面入口留待后续前端；千事暂时没有独立开关或专属时间线页面。
- 原生批量删除聊天末尾后，摘要与 CSE 可回退到保留楼，千人基础资料保持最新版；既成卡档可在记忆管理点击“刷新状态”，经安全完整读回核验后恢复，普通打开不自动恢复。
- 在正文生成前根据当前 user 输入、近期上下文与历史事实排序召回；普通召回和前情使用 D2，故事时间仍使用 D0。同一条 user 消息的续写、重生和 swipe 会复用首次召回，不被后台晚到变化改写；局部 CSE 记录损坏时，仍可只读使用通过核心图校验的摘要，新学别名也进入统一人物目录。
- 人物资料批量整理会保存能唯一绑定的合法人物，并在原结果位置说明遗漏、冲突或未知目标。
- 主动人物重新整理不参考旧 AI 档案并替换旧 AI 字段，保留人工字段、头像、排序与重要人物选择；自动更新继续按新材料增量整理。
- 设置页提供总开关、分析／摘要／召回 API、世界书整本排除、正文清洗标签、摘要／人物资料／人物状态提示词、已记忆旧楼自动隐藏、当前聊天记忆删除和外观设置。摘要默认跟随分析，召回默认跟随摘要，也可独立选择共享预设；不同预设仍可能共用同一账号的并发额度。
- 世界书整本排除在读取前生效；异步字体结果仅在对应 URL 仍为当前选择时应用。

主面板分为“千人”“千结”“双丝网”和“设置”四页：分别查看人物资料、逐楼记忆、人物状态以及插件配置。后台记忆和召回不依赖面板保持打开。

同一 SillyTavern 页面里的其他扩展可通过版本化全局桥只读获取当前聊天的记忆文本、最近一次正文生成准备的轻量材料或结构化快照。调用方式与字段合同见 [公开读取 API](docs/public-api.md)。

## 0.4.0

- 新增存储管理：可查看当前记录占用并手动永久清理不再被当前记录引用的旧基础记录；它不处理回收站，自动周期清理默认关闭，开启后才会运行。永久清理需要已发布的新版白鳥后端；未升级后端时普通记忆、删除与恢复仍可继续使用。设置页重新整理了管理区布局，普通删除与恢复仍沿用回收站语义。
- 摘要与人物状态支持关键词搜索和详情查看；人物状态时间线明确区分新增、更新与移除。人物状态完全重构的失败楼号、进度和错误会持续保留在管理页，刷新状态不会把旧失败提示误写成当前读取失败。
- 检测到连续 AI 回复时，可在记忆页确认后分别登记并按顺序摘要。摘要时间兼容正文里的多段时间区间；旧记录只有在当前可靠正文时间回退可用时才显示完整区间。面板标题与人物名不再被固定宋体覆盖，自定义字体设置会作用到这些位置。
- 优化新鲜读取、人工刷新、同 root 复用、人物状态续跑和逐楼读取：健康缓存日常打开不再重复读取整图，root 变化时仍会重新核验；已经提交的人物状态进度会从当前可达记录继续。
- 普通召回与前情的注入深度统一为 D2，故事时间保持 D0。同一条 user 消息首次生成的完整召回会冻结复用，续写、重生与 swipe 不再重复读取来源或重跑选材；删除该 user 楼后创建的新消息仍会重新召回。
- 千事随摘要同次生成，以每楼记忆为唯一权威，保存事件、事项接续和明确先后关系；当前有效楼会派生剧情图并把相关进度纳入普通召回。已提供手动历史补齐接口和公开只读桥，界面入口留待后续前端；没有独立开关，也暂不提供专属时间线页面。旧摘要和旧人物状态不会自动重写。
- 千事输出合同明确使用 `event-N` 事件局部编号及 `candidate-N` 旧事项候选编号，事件关系不再用标题代替编号；单个千事条目有误仍不会触发整次摘要重试或丢失合法摘要。
- 刻度长材料继续使用约 60000 估算 token 的保守输入预算；“千人”多人整档继续使用 60000 字符输入门槛，两者不是同一单位。

## 0.3.0

- 历史补齐和完全重构可选择“高楼压缩模式”：每 10 个连续 AI 楼合成一份范围记忆，并在批末分析一次人物状态，能减少请求与记忆数量，但会主动舍去更多枝节。需要逐楼细节时继续选择普通模式，每楼独立保存与分析。
- 压缩记忆保留实际成员楼来源；成员删除、换绑或来源对象变化时不会注入失效结果。高楼召回提高智能选材输出容量，并在同一 5 秒准备边界内复用经版本核对的快照；普通召回材料总上限提高到约 8000 token，仍按相关性取舍，不会为了填满额度硬塞材料。
- 召回取消旧的固定楼数与人物项数资格帽，聚合同线材料只受最终总预算约束；近期摘要、远期旧事、人物当前状态与历史变化统一去重。楼内召回卡支持更多剧情线，复选框与标题在窄宽度下不再互相挤压。
- “近期事项”增加批量完成、暂停和移除；已明确结束且无持续影响的事项可退出自动跟进，重伤、慢性或仍有影响的事项会继续保留。刻度长材料整理使用最高约 60000 估算 token 的保守输入预算，已保存观察和人工修改保持原有来源含义。
- “千人”可勾选多位人物后一次整档整理，单次输入最高 60000 字符；完整新档替换旧 AI 字段，同时保留头像、排序、重要人物选择与人工内容。成人偏好字段只整理独立、稳定的偏好与边界，剔除具体经历、场景举例和解释。

## 0.2.63

- 新分支首次继承失败并留下没有 root 的半成品后，若再次继承遇到精确记录冲突，会沿原源聊天改用新的独立目标完成复制。旧半成品不删除、不覆盖也不作为来源；已存在 root、读取异常、普通网络或匹配错误仍停止处理。

## 0.2.62

## 0.2.6

- 时间事项某批只有部分结果有效时，成功项继续保存；同一正文不会因刷新或重载反复请求，之后出现新正文仍会正常更新，不再被旧的“部分完成”永久挡住。
- “近期事项”会在能够可靠对应到具体事项时标注本次失败原因，保留原内容，并可沿用现有入口编辑或移除。后续模型成功评估会清除标注；移除失败事项后，仍有其他失败或无法定位错误时继续显示部分完成。正文未检查范围独立保留，不会因移除事项被记作已覆盖。旧记录缺少事项 ID 时不按返回顺序猜测，无法可靠定位的错误仍保留批次提示。

## 0.2.5

## 0.2.4

- 日期读取兼容更多中文、全角、特殊纪年、闰月和星期写法；能确认的时间差继续计算，未知月长的跨月推进不猜。人物资料与用户设定中的生日、明确年度纪念日会增量提取，临近 7 日时参与现有时间参考选材。
- 时间参考使用最多 600 token 的子预算，普通召回总预算保持 4000 token。当前故事时间不再受摘要进度牵连；时间校正或提醒失效时只撤除对应内容，其余已选召回材料继续使用。

## 数据与兼容

千千结通过 ST-BaiNiaoData 的通用记录接口保存记忆数据，并使用 revision/CAS 避免迟到任务或并发写覆盖当前状态。切换聊天、切换 Persona 或关闭插件会使旧会话任务失效；总开关关闭后停止后台读取、AI 任务与召回注入。

同角色分支会获得独立的聊天身份和存储目录。分支初始化完成后，源聊天与分支可分别修改或删除；跨角色复制仍按独立新聊天处理。

删除当前聊天记忆会保留聊天正文和全局 API／提示词设置；后端记录进入回收站，当前不会自动永久清除。移动端面板使用浏览器原生纵向滚动；“详细诊断”可复制最近 24 条本地界面手势状态，不包含聊天正文或输入内容，也不会上传。该诊断用于继续定位偶发滚动问题，不代表所有手机壳浏览器均已完成真机验收。

## 安装

千千结前端与白鳥数据后端是两份插件，需分别安装：

1. 安装 [ST-BaiNiaoData 后端](https://github.com/atonal519/ST-BaiNiaoData)。Luker 可用后台的服务端插件管理；原生酒馆默认将后端放在根目录 `plugins/ST-BaiNiaoData`，确认其中直接有 `index.mjs`，不要多套一层文件夹，也不要装进前端的 `public/scripts/extensions/third-party`。
2. 检查实际运行的酒馆根目录 `config.yaml`：将已有的 `enableServerPlugins` 设为 `true`，不要追加重复键。默认 `serverPluginsPath: ./plugins`，若改过则按其路径安装；`enableServerPluginsAutoUpdate` 只控制自动更新。
3. 安装或改配置后完整重启酒馆服务，再刷新网页。仅刷新网页或切换千千结开关不会加载服务端插件。
4. 在酒馆第三方扩展安装入口粘贴本仓库 URL。面板入口位于魔法棒菜单，也可在设置中开启悬浮球；生产清单只加载 `dist/qqj-app.js`。打开实际聊天后配置模型 API，新聊天逐步记录，旧聊天按需要手动补齐。

遇到 404、持续读取中或记忆突然为空，先看 [排障手册](docs/troubleshooting.md)。模型 API 和记忆存储后端的错误要按失败地址区分；排查后端加载不需要删除记忆或完全重构。
