# Myriad Knots（千千结）

`ST-MyriadKnots` 是 SillyTavern 的长期记忆扩展，界面中文名为“千千结”。项目仓库：[github.com/atonal519/ST-MyriadKnots](https://github.com/atonal519/ST-MyriadKnots)。

## 当前功能

- 为每个聊天建立稳定身份，并保持聊天、角色卡与 Persona 之间的数据隔离。
- 从稳定 AI 楼提取带证据的 FloorMemory；支持历史重建、断点继续、逐楼重算和用户修订摘要。
- 已保存楼的正文后来发生普通编辑时，用户仍可基于当前正文修订摘要、时间、地点和人物；保存前后若目标再次变化则拒绝迟到写入。
- 以正文为最高事实源，通过 CSE 维护人物核心、适应性与情境状态；坏条目不会误清空旧分类，合法证据也不会被同批坏引用连坐。
- 在正文生成前根据当前 user 输入、近期上下文与历史事实排序召回；局部 CSE 记录损坏时，仍可只读使用通过核心图校验的摘要，新学别名也进入统一人物目录。
- 人物资料批量整理会保存能唯一绑定的合法人物，并在原结果位置说明遗漏、冲突或未知目标。
- 设置页提供总开关、主/副 API、世界书整本排除、正文清洗标签、摘要／人物资料／人物状态提示词、已记忆旧楼自动隐藏、当前聊天记忆删除和外观设置。
- 世界书整本排除在读取前生效；异步字体结果仅在对应 URL 仍为当前选择时应用。

主面板分为“千人”“千结”“双丝网”和“设置”四页：分别查看人物资料、逐楼记忆、人物状态以及插件配置。后台记忆和召回不依赖面板保持打开。

同一 SillyTavern 页面里的其他扩展可通过版本化全局桥只读获取当前聊天的记忆文本或结构化快照。调用方式与字段合同见 [公开读取 API](docs/public-api.md)。

## 0.1.16

- 历史补齐会先处理摘要，再处理 CSE。某楼摘要最终失败时会跳过该楼并继续后续楼；只有 CSE 自身失败才会停止 CSE 阶段，已保存结果都会保留。
- 摘要提取与 CSE 分析各自最多发出 3 次请求；可恢复错误会沿用原错误类型重试，取消后不再继续。正文召回仍保留原来的一次重试。
- 同一浏览器会按聊天保留 CSE 逐楼失败和自动任务外层失败提示，刷新后仍可核对。
- 设置页最底部新增与通用设置同级的“教程与配置文件”抽屉；其中保留完整 8 节教程文档，并集中放置 API 说明、示例和复制功能。

## 0.1.15

- 召回模型发生 API 或网络等技术故障时，整轮选材会再尝试一次；第二次仍失败则可靠停止本次正文生成。正常完成但没有可靠命中的情况仍按空召回处理。
- 双丝网某个关系方向当前为空时，只读显示该方向最后一次已保存的历史关系和实际楼号，不改写当前人物状态。
- 版本化公开桥新增同步 `getSnapshot()`，以独立副本读取当前已加载的摘要、CSE 与千人档案；记忆管理页新增默认折叠的“API 接口”调用说明。

## 0.1.14

- 可在当前聊天的记忆管理页粘贴长篇前情；原文随聊天保存，生成正文时按相关性选段，并与普通记忆共享原有预算。
- CSE 分析和人物资料整理会参考相关前情；首次整理人物时参考范围较大，后续更新使用较小范围，人物长资料仍沿原流程分批处理。
- 提交记忆时会复用本次会话中已确认写入的内容，减少重复读取；若摘要已经生成但保存失败，在原正文与处理提示未变化时，手动继续会复用这次结果。

## 数据与兼容

千千结通过 ST-BaiNiaoData 的通用记录接口保存 V3 数据，并使用 revision/CAS 避免迟到任务或并发写覆盖当前状态。切换聊天、切换 Persona 或关闭插件会使旧会话任务失效；总开关关闭后停止后台读取、AI 任务与召回注入。

删除当前聊天记忆会保留聊天正文和全局 API／提示词设置；后端记录进入回收站，当前不会自动永久清除。移动端面板使用浏览器原生纵向滚动；“详细诊断”可复制最近 24 条本地界面手势状态，不包含聊天正文或输入内容，也不会上传。该诊断用于继续定位偶发滚动问题，不代表所有手机壳浏览器均已完成真机验收。

## 安装

先独立安装并启用提供通用记录接口的 ST-BaiNiaoData 后端，再在 SillyTavern 的第三方扩展安装入口中粘贴本仓库 URL。生产清单只加载 `dist/qqj-app.js`；面板入口位于魔法棒菜单，也可在设置中开启悬浮球。
