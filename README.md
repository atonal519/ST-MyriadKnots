`ST-MyriadKnots` 是 SillyTavern 的长期记忆扩展，界面中文名为“千千结”。项目仓库：[github.com/atonal519/ST-MyriadKnots](https://github.com/atonal519/ST-MyriadKnots)。

当前版本 **1.2.2**，完整改动见[更新说明](CHANGELOG.md)。

## 当前功能

- 搬家与普通分支复用现有批量保存和核心缓存，保持原档与新档独立；主程序和稳定地图／图标素材分包，未变素材可继续命中缓存。
- 千窗设施标签补充罗汉榻、博古架、香炉、屏风、油灯、火炉等古风器物，复用现有单色线稿，明确空设施列表保持为空。
- 公开只读 `readContext` 支持话题重点、参与人物与摘要数量／字符预算，供构画等调用方读取已存记忆；参数与局部分区状态见[公开 API 文档](docs/public-api.md)。
- 本楼有来源的人物首次出现即可参与 CSE 检查；提及或观察不等于在场、知情或可推断内心。人物状态召回按同一相关性标准竞争；场景状态标明为已保存快照，同次选材对照清洗后的最近正文与同源原文、摘要，双丝网沿人物条查看你与选中人物的双向关系，也可核对其与其他人的记录。旧经历与人工修订保留，旧楼不会自动重新分析。千人“更多人物”支持按姓名、原名或别名搜索。

- TauriTavern 高楼层记忆按批读取，每批最多 64 条、原生读取最多 8 路并行；“设置 → 记忆设置”提供既有 IndexedDB 缓存开关，再次打开时按当前根版本复用已验证的核心记录。关闭或缓存不可用时从正式存储读取，修改开关后整页刷新生效。
- TT 2.4.0 Windows 导入收尾只保存撤销所需的千千结字段，避免把完整聊天正文和其他插件变量再写入一条超大备份；旧撤销记录继续兼容。原生读取省去一次重复 JSON 深复制，保留现有存储格式与版本校验。
- 为每个聊天建立稳定身份，并保持聊天、角色卡与 Persona 之间的数据隔离。
- 从同一角色聊天创建分支时，按酒馆已复制消息携带的记忆楼标记，对应继承实际保留范围内已有的摘要、人物状态及兼容有效的原文向量，并沿用这些人物的最新版资料及整套最新地点档案与人工修订。地点在各分支独立保存。首楼或中间尚未记忆的消息不会阻断已有记忆的继承。旧正文措辞或宿主显示变化不会截断继承；源缺失的结果保持缺失，范围外的后续楼不带入，向量复制不调用 embedding。
- 从稳定 AI 楼提取带证据的 FloorMemory；支持历史重建、断点继续、逐楼重算和用户修订摘要。
- 地点路径与空间记录沿明确关联复用同一地点身份，保留建筑、楼层和房间之间有据的中间层级。同次摘要分别记录有据的重要稳定设施与临时现场；地点有真实新信息时，在同一次请求中合并更新当前简介与方位，保留未改变的设施，不再追加一段复述。千窗“整理”会根据完整目录和来源识别同一地点的不同称呼，合并模型明确指定的重复地点并承接资料和子地点；双方人工字段冲突时保留目标已有值，含空值，源地点只补未设字段。也会归并已有重复段落和同义方位；原楼事实与引文保留，可按当时范围查阅。临时现场和旧未分类描述保留来源楼历史含义。空间包含、场所归属、所在楼层与相对位置分别保存；较新材料只重述祖先归属时保留已明确的中间父级；有据修订可改父或撤销旧自动所属，后续材料仍可补全，人工父级优先。整理按原来源补归属上下文并合并重复片段；候选目录之外的同名/别名也参与身份冲突检查。召回沿原一次选材和预算，不自动重提或改写旧档。
- “千窗”按父子层级浏览地点，地区筛目录、场地点展开描述，房间与楼层逐层查看。当前位置显示为单个重点色水滴图钉，其他场地显示圆点；点击图钉可原位展开当前用户头像，并展开当前房间及上级目录；再点只收起头像，点空白收起头像并清除目录选择。上方位置文字会展开并定位到已记录的具体楼层或房间。可编辑所属地点、地点类型（区域、场地、室内或自动）和地图层级，或在同一编辑草稿中添加已有子地点；未归属记录保留在折叠目录，不额外生成地图页。“初始化”用一次摘要 API 通读当前允许读取的世界书，补入尚未登记的地点与明确层级；“整理”用一次摘要 API 校对已有地点及其保存来源，合并别名、重复资料并整理归属、简介、设施与底图，可补明确缺失的上级。两个入口都保留剧情变化、人工修订和删除，可反复使用。城市、独立地域、巨舰与星球可分别浏览，当前所在地的地图页排在最前，手动选中的页面保持；国家保留所属关系而不单开总览。地点目录独立保留最新资料，分支截点、删楼或回退不撤销整理结果；当前位置仍按本聊天的剧情记录。普通新增摘要和最新一楼重新提取会参考最新地点父树，历史重新提取仍按所选楼的历史范围取材。
- 地点按范围、题材和地貌自动选背景，已有选择保持稳定；24张通用图覆盖现代城市、小城、古风城镇、自然地形、宫苑、舰内和校园，十个真实城市另有对应背景，支持已收录的常用别名。本丸、和风御殿等独立日式生活院落可选本丸底图；同题材中的城镇或野外仍按各自环境选图。校园按真实空间选紧凑、园林或综合大学底图，高中和小大学可共用紧凑或园林；私立身份不决定版式。地图目录与图片默认从免费静态图库读取，访问取决于设备网络；连不上时，现有图使用随插件保留的本地素材，地点目录仍可查看。之后新增且尚未内置的图片需要联网读取，同类新图发布到图库后刷新酒馆即可参与选择。地图显示区统一为方形，底图、分区与点位在内部按原比例居中；场地点位是关系示意。旧档需要补层级、分图或调整题材时，可在千窗正常点“整理”。
- 手动历史补齐与完全重构在首楼建立人物状态基础后，后一楼摘要可与前一楼 CSE 同时请求，每路最多一个请求。摘要或人物分析的单楼失败分别保留待补，健康后楼继续处理，已保存结果保留；只补人物分析缺口时复用已有摘要。记忆管理按当前任务更新进度，任务结束后显示最新结果；继续补齐接着原任务处理待补范围，入口随正文生成和后台工作的实际状态更新。
- 普通聊天的完全重构会删除当前聊天全部千千结记录及前情，再以新身份从正文重建；合并聊天会保留归档历史、千人人物资料（含头像与重要人物选择）和前情，只重做当前部分的摘要、人物状态与时间事项。普通“删除当前聊天记忆”仍保留前情；两种操作都保留聊天正文、其他插件数据和全局设置。
- 已保存楼的正文后来发生普通编辑时，用户仍可基于当前正文修订摘要、时间、地点和人物；按稳定目标与实际修改字段保存，承接已有人工值；目标已删除或同字段发生人工竞争时保留当前结果，草稿仍可继续编辑。
- 一楼正文待同步时，其余可对应的记忆继续召回；该楼旧自动材料暂不入池，已保存的手工摘要仍以人工内容为准。同一轮再次生成会更新已选中的手工摘要，不额外请求选材模型。
- 摘要时间优先读取标准 QQJ/SDC/myknots 时间戳；缺少标准时间戳时，可从正文原文中的成对标签补充完整时间参考。补充标签默认留空，可在设置中显式填写 `Ti` 或其他自定义标签。该设置只影响后续摘要提取，不改变正文清洗，也不会自动重做旧摘要。
- 主动“重新提取本楼”会先保存当前 AI 消息的本楼标记，再按所选正文提取摘要；缺标或改过正文也可使用，人工修订沿原规则保留。
- 人物或地点辅助资料暂不可读时，按类别停用受影响的自动材料，普通旧事继续使用。地点处理发生局部错误时，其他可用摘要、人物和记忆继续处理。已选地点的人工改删刷新本轮对应部分，无关地点和地图样式改动保留已完成选材。
- 记忆待核对时，已保存的本聊近期事项仍可查看、编辑和停止。时间推演使用有效剧情来源。
- 人工修订优先；未人工修订的内容以正文为事实源，通过 CSE 维护人物核心、适应性与情境状态；坏条目不会误清空旧分类，合法证据也不会被同批坏引用连坐。
- CSE 请求中的人物相关 FloorMemory 证据按原数组索引引用，避免同一条目随多个主体重复发送；仅省略 Core/Adaptive 前态的旧 reason，Situational 原理由和完整历史状态继续保留。兼容部分 CSE 回复中段少一个闭合括号的情况，并在同一人物顶层缺少情境状态时读取 review 中已有字段。
- 可选时间推演默认关闭，直接读取当前选中、清洗后的 AI 正文，使用摘要 API 追踪身体状态、周期与约定期限，摘要与 CSE 可为空。历史观察满足时间条件时可同次登记并推算到当前，未知或倒退时间不强算；推测独立保存，不改写旧 CSE，也不是已发生的新事实。普通编辑旧楼正文或时间标签不会自动撤销已存时间事项或触发重查；新批次有完整时间标签见证时，时间戳文字变化只提示核实，旧批次缺少见证时不猜。
- “千结 → 近期事项”可折叠查看、编辑和整理当前追踪清单；可更改人物归属，也可修改弹窗显示的“当前推测”。只改人物或推测会保留原推算时间，修改其他内容会清除旧推测。“补查历史”先显示待查楼数、预计批次和 API 调用量，确认后分批读取正文。楼内召回框默认收起，展开后按“旧事”“人物”“物”查看目录。旧事按近期接续、相关旧事直接列出；人物状态与变化合看，当时承诺和计划单列；物页只呈现本轮实际带入的千事进度、近期事项和地点参照。同一地点的当前资料合占一项，简介、归属、方位和来源合看；同地点、同一完整引文来源的重复短陈述只显示一次，人工原文和全部来源保留；普通召回不再独立带入旧楼地点标注；旧事摘要中的地点文字和地点档案照常保留，旧回执仍显示当时内容。物页不显示来源楼号，约定、观察和推算时间照常显示。点击整条目录原位展开，点标题收起；正文可选取复制，同一列表一次打开一项；完整注入及本轮千事、时间和地点参照可在“设置 → 记忆管理 → 最近召回回执”核对。时间推测单列推算时点；追踪清单数量与本轮注入数量分别统计。
- “设置 → 记忆设置”可为当前聊天确认固定历法：12个月使用普通大小月、二月28天，不计闰年；4个月每月30天，春夏秋冬依次对应1至4月，支持“春1日”“夏10日”及“春月1日”。“特殊年”只填年份前的完整纪年名称，例如“启航387年”填“启航”，不填数字或“年”；年份仍取日期原文。规则用于时间轴排序与时间间隔，独立于时间推演开关；保存设置不调用模型或改写旧记忆。
- 千事随新楼摘要在同一次请求中提取独立事件、事项进展和明确先后关系，并参与普通召回；旧摘要不会自动补写千事。主面板“千事”页展示完整已保存年表与事项经过，并可在明确确认后手动补齐旧楼；已判定为空的单楼可在补齐计划中显式选择重查，已有事件、人工删除、审核候选和聚合来源仍保留原保护。同日事件分别保留并可搜索；年表按剧情日期从新到旧排序、同月归组，并标记最新日期。日期默认展开可靠的最近日，否则展开当前排序首日，折叠日期显示当天最后一件事件的时间、标题和简短说明。编辑时可多选人物、按姓名或别名搜索候选，并按需添加约定 / 预计时间；千事没有独立开关。时间支持十二时辰和初正范围，明确初正的刻按十五分钟细分（初刻及一至三刻），未分初正的刻不猜具体钟点。
- 原生批量删除聊天末尾后，摘要与 CSE 可回退到保留楼，千人基础资料保持最新版；既成卡档可在记忆管理点击“刷新状态”，经安全完整读回核验后恢复，普通打开不自动恢复。
- 新聊已有历史仍完整位于保留的 N 个 AI 正文范围内时，跳过普通召回和选材调用；N 跟随保留楼数设置，摘要与人物状态照常记录。显式前情、搬家归档和更早历史继续沿原合同处理。
- 在正文生成前根据当前 user 输入、近期上下文与历史事实排序召回；普通召回和前情使用 D2，故事时间仍使用 D0。同一条 user 消息的续写、重生和 swipe 会复用首次召回，不被后台晚到变化改写；首次提交会复核所选摘要和历史事实的版本，避免选材期间来源更新后注入旧内容。人物状态会区分面向不同对象的相同文字；近期摘要只有分别覆盖变化前后两侧才会去重。局部 CSE 记录损坏时，仍可只读使用通过核心图校验的摘要，新学别名也进入统一人物目录。
- 新加入且基础资料为空的重要人物，会在当前聊天空闲时自动做首次整理并调用摘要 API，参考已记录的目标事实、原句出处及许可世界书，不重读整楼全文。已有资料不会自动首次重整；每约十个新增稳定 AI 楼仍轻量粗扫有资料的人物近期原文。手动重整以旧 AI 资料为待核底稿纠错补齐，未覆盖细节保留；非人工别名重新筛选完整稳定名单，之后粗扫只补稳定新增。人工字段含空值始终优先。单人重整一次请求完成，失败保原档；未返回有效别名时保旧名单并提示。缺档批量整理沿原分批规则，已记录材料未覆盖的原文细节不会补猜。
- 千人资料新增独立血型、星座、体重、国籍、出生地、常住地、使用语言、技能与能力、MBTI、九型人格和道德阵营；只填明确材料。下一次原有整理可同次拆分旧资料，保留人工字段与独有事实，直接陈述事实和必要时期，不写来源核对评语。纯人类种族只在阅读时隐藏，编辑与存值保留。
- 确认保存的新生成原图可在柏宝绘图库的对应角色卡分组中查看、删除；上传原图保留原处。头像完整图保存在酒馆用户图片目录，工作区仅保存引用与取景；完整迁移用户数据时，请同时保留酒馆图片与千千结数据。
- 千人人物菜单可通过柏宝绘角色库生成头像，完整预览后确认保存，可自行裁剪或保存原图；裁剪只影响头像显示，点击头像可查看保留的完整图，替换沿人物菜单操作。外貌使用现成角色档案，并参考人物资料里已保存的衣着风格，不调用文字模型。可在“设置 → 通用设置 → 提示词与包裹符 → 头像生图提示词”编辑构图提示词。
- 近期事项弹窗提供“新增”，可手动登记人物的身体状态、周期或期限，时间未知可留空；千事工具栏提供“新增待办”，保存到千事并开始跟进。人工新增不调用模型，后续沿原流程更新；待办不会自动再复制成近期事项。
- 剧情提取、人物状态与资料、千事和近期事项在原有分析中并读配对的 AI 与 USER 材料，历史使用已保存的来源。千事分别判断事实状态和跟进价值：上下文已交代目标达成可完成；日常安排已带过可停止跟进，人工选择优先。关联待办停止跟进后，近期事项保留原记录并列入“已停止”。
- 完整 HTML、HTML 代码围栏和明确保留正文内的排版会去壳留字，思考、状态与清洗块继续剔除。自定义正文包裹符仍需在保留标签中显式配置。
- 自动主题按酒馆提供的文字、强调色和背景变量配色，保留可读的宿主颜色，校对主面板、弹窗、提示文字和按钮的搭配。透明底色先合成再判断，切换酒馆主题时同步更新。可在“设置 → 通用设置 → 外观”选择“跟随酒馆”、手动日间或夜间。
- 设置页提供总开关、分析／摘要／召回／向量 API、世界书整本排除、正文清洗标签、摘要／人物资料／人物状态提示词、已记忆旧楼自动隐藏（默认开启）、当前聊天记忆删除和外观设置。摘要默认跟随分析，召回默认跟随摘要，也可独立选择共享预设；不同预设仍可能共用同一账号的并发额度。 API 配置外部保留各用途选择与编辑，连接字段在弹窗中保存或取消。下方“新增 API”只建立共享连接，不改变当前用途；名称、拉取模型、高级参数、测试、另存与删除均在编辑弹窗内。高级参数中的“失败重试次数”控制文字请求，默认 2 次；0 不重试，N 表示首次失败后最多再试 N 次。网络、超时和格式重做共用这份额度。
- 可选向量召回默认关闭。“设置 → 通用设置 → 向量配置”中有独立选项，URL 和模型已填好硅基流动与 `Qwen/Qwen3-Embedding-8B`，填写 Key 后可保存或测试连接；为当前聊天建立索引会请求向量 API。“记忆管理”的“还没有向量索引，去建立吧”链接只打开此设置，不会自动建立索引或请求模型。有效索引召回到 0 个候选，与没有索引不同。讯飞 MaaS v1/v2 会自动使用酒馆原生 CORS 代理，需在酒馆配置中开启并重启；模型名由用户手动填写。点击“建立索引”处理当前聊天，可取消；切页回来可继续查看进度。符合来源条件的楼统一建立原文索引，手动编辑或清空摘要不改变其原文资格；首次手动建索引后，稳定且记忆已保存的新楼会自动补齐，楼删除或原文改变会从后续索引中撤下或更新。旧摘要专用向量缓存仍可读取，但不会参与新查询；仅有这类旧索引时，需手动重建原文索引。首次召回读取现成索引最多等待 15 秒；向量查询每次最多等待 15 秒，超时最多补试一次，同一轮（含整轮重算）最多发送两次请求。仍未取得候选、索引读取超时或接口失败时沿用原召回。向量补充候选仍由同一次 LLM 筛选，最终共用原有最高 8k 预算。
- API 高级设置支持“附加参数（JSON）”，按当前配置保存。关闭思考：智谱 API 可填 `{"thinking":{"type":"disabled"}}`，Ollama 兼容接口可填 `{"reasoning_effort":"none"}`；留空沿用默认，实际支持以模型接口为准。
- 召回核验完成后即可生成正文，回执在后台保存；保存状态与分段耗时可在召回详情查看。提交核验可直接读取已完成的记忆快照，减少等待后台维护。
- 世界书整本排除在读取前生效。角色绑定主外置世界书时只以外置为准，不从卡内副本补回条目，外置为空、被排除或读取失败也不会回退；无主绑定的内嵌书继续可用，角色辅助书独立读取。异步字体结果仅在对应 URL 仍为当前选择时应用。

主面板分为“千人”“千结”“千事”“千窗”“双丝网”和“设置”六页：分别查看人物资料、逐楼记忆、剧情年表、地点地图、人物状态以及插件配置。手机主面板按浏览器可视窗口显示，左右各留 10px，通常上留 20px、下留 60px，顶部位置以屏幕安全区为界，点击面板外侧空白可关闭。桌面默认 360×600，可在整个浏览器可视范围内拖动或调整尺寸，重新打开时使用已存尺寸和位置；可视空间不足时自动缩小至完整显示。后台记忆和召回不依赖面板保持打开。外观中的界面缩放继续调整字体；纯图标控件保持固定大小，带字按钮按文字自然撑开或缩小。

当前单人聊天的记忆可在“设置 → 记忆设置 → 存储管理”最下方导入与导出。换设备时，先在旧设备等待记忆任务完成，同时导出酒馆聊天 JSONL 和千千结记忆包；新设备先导入并打开对应聊天，再选择记忆包，预览后确认导入。两端都需要安装带有此功能的版本。

普通导出和旧版 v1/v2 JSON 记忆包继续使用 64 MiB 上限。更大的档案可点击“自动导出大记忆包”：支持文件直写的浏览器选一次保存位置；TT 2.4 在浏览器临时文件中逐卷写完，再一次性保存。生成的 `.qqj-memory` 文件已包含清单，导入时只选择这个文件。其他 ST/TT 环境会自动依次提交各卷和最后的清单，可能需要允许浏览器连续下载；请在下载列表核对全部文件已保存。旧分卷仍可导入，需要同时选择清单（`.qqj-memory.index.json`）和全部卷（`.qqj-memory.part-0001.bin` 等），并保留原文件名。大记忆包可超过 1 GB，导出和导入均按约 8 MiB 的卷处理，不会整包读入内存；单条记录特别大时仍需相应内存。取消或导出未完成的文件不能导入。

记忆包包含摘要、人物状态与资料、人物头像及原图、千窗地点资料与人工修订、千事事件与事项进度、时间记录、向量缓存、前情和当前聊天历法，也保留“不计入记忆”等楼层标记。人工修改、清空和删除均按当前保存结果迁移，不会重新生成。记忆包不包含 API 密钥或全局配置；使用自定义正文清洗规则时，请先在新设备设置与旧设备相同的保留标签和额外清洗标签，再导入记忆包。导入后可重新打开聊天查看；导入后的记忆和聊天正文均未继续变化时，可点击“撤销上次导入”恢复原记忆。

同一 SillyTavern 页面里的其他扩展可通过版本化全局桥只读获取当前聊天的记忆文本、最近一次正文生成准备的轻量材料或结构化快照。调用方式与字段合同见 [公开读取 API](docs/public-api.md)。

常见问题可先看应用内“设置 → 教程与配置文件 → 教程文档”；完整排查步骤见[排障手册](docs/troubleshooting.md)。

本次版本的完整改动说明见[更新说明](CHANGELOG.md)。

## 数据与兼容

普通 SillyTavern/Luker 通过 ST-BaiNiaoData 的通用记录接口保存记忆数据，并使用 revision/CAS 避免迟到任务或并发写覆盖当前状态；TauriTavern 2.2.0 使用原生扩展存储，详见 [TauriTavern 指南](docs/tauritavern.md)。异步任务按开始时确定的业务目标处理；切换聊天不取消仍有效的任务。关闭插件总开关后会停止后台读取、AI 任务与召回注入。

同角色分支会获得独立的聊天身份和存储目录。分支初始化完成后，源聊天与分支可分别修改或删除；跨角色复制仍按独立新聊天处理。

删除当前聊天记忆会保留聊天正文和全局 API／提示词设置。存储管理中的“清理旧版本”只清理当前聊天已不再被数据引用的后台文件；进入千千结回收站的记录保留 30 天，到期后空闲时自动分批清理，也可手动清理到期记录，当前数据和未到期记录保留。旧版白鳥后端若不支持回收站清理，需更新后端后重启酒馆服务；普通前端更新后刷新页面即可。移动端面板使用浏览器原生纵向滚动。记忆管理仍可复制状态诊断；启用本机诊断后，摘要失败及有限前文差异会自动留存，便于排查未保存原因。

## 安装

### TauriTavern 2.2.0

在 TauriTavern 2.2.0 中安装千千结前端即可：数据保存在 TauriTavern 提供的原生扩展存储中，不需要安装 ST-BaiNiaoData 服务端插件，也不需要为它配置或重启 SillyTavern 服务。已有 TauriTavern 千千结档案可继续读取；数据不会自动迁移到白鳥服务器，也不会与服务器数据同步。存储细节见 [TauriTavern 指南](docs/tauritavern.md)。

### 普通 SillyTavern/Luker

普通 SillyTavern/Luker 需要分别安装千千结前端与 ST-BaiNiaoData 服务端插件：

1. 安装 [ST-BaiNiaoData 后端](https://github.com/atonal519/ST-BaiNiaoData)。Luker 可用后台的服务端插件管理；原生 SillyTavern 默认将后端放在根目录 `plugins/ST-BaiNiaoData`，确认其中直接有 `index.mjs`，不要多套一层文件夹，也不要装进前端的 `public/scripts/extensions/third-party`。
2. 检查实际运行的酒馆根目录 `config.yaml`：将已有的 `enableServerPlugins` 设为 `true`，不要追加重复键。默认 `serverPluginsPath: ./plugins`，若改过则按其路径安装；`enableServerPluginsAutoUpdate` 只控制自动更新。
3. 安装或改配置后完整重启酒馆服务，再刷新网页。仅刷新网页或切换千千结开关不会加载服务端插件。
4. 在酒馆第三方扩展安装入口粘贴本仓库 URL。面板入口位于魔法棒菜单，也可在设置中开启悬浮球；生产清单只加载 `dist/qqj-app.js`。打开实际聊天后配置模型 API，新聊天逐步记录，旧聊天按需要手动补齐。

遇到 404、持续读取中或记忆突然为空，先看 [排障手册](docs/troubleshooting.md)。模型 API 和记忆存储后端的错误要按失败地址区分；排查后端加载不需要删除记忆或完全重构。

## 开发测试

运行 `npm test` 执行测试，`npm run build` 更新生产包。预设共享的真实跨插件联动子用例需要 [ST-SevenDaysCal 源码](https://github.com/atonal519/ST-SevenDaysCal)，默认读取同级目录，也可用环境变量 `QQJ_SEVEN_DAYS_CAL_ROOT` 指定源码根目录。未提供且同级源码不存在时，只跳过该联动子用例，千千结自身的配置隔离与共享预设测试仍照常执行。
