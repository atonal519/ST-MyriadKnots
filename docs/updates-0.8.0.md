# 千千结0.8.0更新说明

这轮整理千人、千结、千事、双丝网和召回流程，并合入此前已单独发布的 0.7.14–0.7.21 性能优化。已有存档继续使用；前端更新不会自动重新分析旧楼。

## 界面与编辑

- 人物资料、逐楼摘要、近期事项、千事、双丝网状态、前情和长提示词统一使用弹窗编辑。调整分组、标题、缩进、字号与按钮对比，并修复部分宿主主题下浅色卡片配浅色文字的问题。
- 多选人物时可按姓名或别名搜索；候选列表在弹窗内滚动。编辑弹窗保留分组折叠、草稿和明确的保存/取消入口。
- 教程、README 和排障说明已按当前界面与实际操作同步。

## 千人：人物资料

- 多人卡整理时，取材不再仅限卡名人物；模型按明确的人物归属提取资料。相同内容沿用已有保存合同，人工字段继续受保护。
- 人物状态中的人物与关系对象按实际身份区分，身份部分采用双丝网展示。说明和提示词更清楚地表达证据范围，但模型整理仍需以保存内容为准。
- 人物档案内容未变时复用已有投影，减少状态通知造成的重复列表计算和页面重建。

## 千结：摘要、地点与历史

- 摘要按楼序从近到远显示，每页最多 50 楼；搜索覆盖全部已保存摘要，再对匹配结果分页。打开搜索命中时会转到该楼所在页。
- 折叠的楼层诊断在展开时构建并复用；直接进入目标设置时只构建对应页面。
- 地点提取可参考前楼已保存的地点和父级关系，帮助承接简称与同名房间；地点身份、包含关系及人物位置仍按各自证据保存，没有依据时不猜补。
- 摘要地点可显示父级到房间的路径，关系以该楼保存的内容为准。
- 归档来源继续使用归档楼的正文、时间与顺序；不会借用当前聊天相同楼号的内容。新规则不自动重算旧摘要。
- 搬家时只核对所选回复正文及千千结自有字段，不因其他显示字段变化而拦截。
- 新聊天或停用后换卡再启用时，身份准备失败会按实际原因反馈；记忆尚未开始的普通新档保持待记录状态。

## 千事：事件与剧情时间

- 事项按明确的可比时间排序；不完整或不同历法的时间保留来源次序，不推测跨年关系。同日事件继续分别展示。
- 改善大时间桶和多条先后关系的排序计算，同时保留来源顺序、明确关系和人工修订结果。
- 千事按由近及远排列；可编辑关联人物，姓名别名可以点选，预计时间可按需填写。
- 搜索、近期事项和回执按保存的事件与来源关系展示。仅当弹窗显示“当前推测”时可修改它；取消编辑不保存。

## 双丝网：人物状态与知情边界

- 精校人物核心、适应性和情境状态的取材说明，区分人物自身状态、针对他人的关系，以及信息的发送、接收和共享依据。
- 多人卡中的具名人物只按明确归属提供核心设定和长期倾向参考；这会改善取材依据，不保证模型识别所有字段或永不遗漏。
- 双丝网主动完整重建时，会按当前用户人设重新检查核心提取；人工修改继续优先，旧记录不会因提示词更新自动重跑。

## 召回、向量与存储

- 回执保留人物变化的目标对象。旧回执若无法拆成页签，可展开查看已有原文；只读入口按需读取人物、话题和世界书材料，不调用模型。
- 后端支持批量读取时，大型冷读按最多 64 条分组，并使用轻量记录清单；较旧后端继续使用逐条读取，回落并发保持有界。存储检查按批次处理，减少完整记录清单在前端的暂存。
- 分支继承和搬家复制已有向量时按小批次读取与写入，不额外调用 embedding。现有来源资格、索引状态和失败诊断保持有效。
- 索引中没有候选与当前聊天尚无索引会分别显示，便于判断是否已有可用结果。
- 点击“去建立向量索引”只打开设置；“测试连接”或“建立索引”会调用已配置的向量 API。

## 清理与旧档

- 清理旧版本的范围是当前聊天。回收站记录到期满 30 天后，按千千结自己的记录范围清理，并保留未到期记录；两类清理彼此独立。取消人物或摘要编辑不写入。
- 普通前端更新后刷新酒馆页面即可，不需为本次变化重启酒馆。只有旧版白鳥后端不支持回收站清理时，才需更新后端并重启酒馆服务；支持批量读取时会自动使用该能力，旧后端沿用原读取方式，前端更新不强制升级后端。
- 新的提取与状态说明用于之后的分析。如需让旧楼采用新提取规则，可主动补齐、重算或重建；本次更新不会批量改写旧档。

## 已发布优化合入

以下性能优化已在 0.7.14–0.7.21 单独发布，本次保留并与当前实现整合：

- 0.7.14：大型存档冷读按有界批次读取；存储统计分批处理；支持批量读取的白鳥后端可启用该能力，旧后端仍可使用。
- 0.7.15：设置页减少重复绘制；楼层诊断延迟到展开时构建。
- 0.7.16：大型导入存档减少重复计算；归档时间不借用当前聊天时间；摘要按完整剧情顺序显示。
- 0.7.17：大型历史补齐减少重复整理旧摘要来源信息。
- 0.7.18：保存、冻结历史、人物与时间状态减少重复计算；摘要按需构建并复用页面。
- 0.7.19：摘要分页；千事补齐、重判和公开读取减少重复投影、校验与快照复制。
- 0.7.20：修复部分合并聊天在摘要和人物状态完成后，旧楼仍未自动隐藏的问题。
- 0.7.21：分支和搬家复制已有向量时减少重复请求与串行等待。

提取流程也整理了正式回答解析、摘要与动作提示，以及明确结束时间和完整时间区间的处理。它们用于之后的分析，不会自动改写旧楼或保证模型在任何文本中都能提取到全部信息。

这些优化不会要求用户重新迁移存档。离线验证不替代 NAS、浏览器或手机上的实测，也不代表已排除所有卡顿原因。
