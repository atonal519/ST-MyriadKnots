# 千千结排障手册

先保留完整提示，再确认失败发生在哪一步。排查加载或连接问题不需要删除记忆；“完全重构”会清除当前聊天的千千结记录及前情，包括人工资料、时间事项等，再从正文建档，正文会保留。它是重建操作，不是安装修复。

## 后端有没有正确安装

千千结是浏览器里的前端扩展，白鳥数据 ST-BaiNiaoData 是保存记忆的服务端插件；模型 API 又是另一项配置。三者需要分别检查。

- 后端来自 [ST-BaiNiaoData 仓库](https://github.com/atonal519/ST-BaiNiaoData)。Luker 可用后台的服务端插件管理安装。原生酒馆默认应存在 `plugins/ST-BaiNiaoData/index.mjs`，路径从实际运行的酒馆根目录算起；解压后不要变成两层同名文件夹。后端不要装进千千结前端所在的 `public/scripts/extensions/third-party`。
- 打开实际运行实例的根目录 `config.yaml`，找到已有的 `enableServerPlugins`，确认值为 `true`，不要重复追加同名键。默认 `serverPluginsPath` 为 `./plugins`，若修改过则按配置路径安装。`enableServerPluginsAutoUpdate` 只管自动更新，关闭它不等于关闭插件加载。
- 安装或修改配置后，完整重启酒馆服务，再刷新网页。只刷新网页、重新打开面板或切换千千结开关都不能加载服务端插件。若仍失败，查看酒馆启动日志是否出现插件加载错误。

## 404 要看失败地址

| 失败请求 | 怎么判断和处理 |
| --- | --- |
| `/api/plugins/st-bainiaodata/v1/health` 找不到 | 优先查服务端插件目录、启用配置、是否重启及启动日志；远程访问还需查代理路由。 |
| `GET /api/plugins/st-bainiaodata/v1/records/.../ID` 返回 `not_found` | 表示这条记录不存在。新档未记录、尚无时间事项而缺时间头记录可能正常；旧档突然全空或持续失败需继续核对。 |
| 模型服务地址上的 404 | 查模型 API 地址、模型名和当前预设，并保留完整错误；不要用删除记忆解决。 |

空集合的查询正常返回 `200` 和 `[]`。千千结的通用后端错误只保留状态码，没有解析错误响应正文，所以单独一个“HTTP 404”不能证明是哪种原因；也不能把所有记录 404 都当正常。模型“测试连接”成功只证明该模型测试请求成功，不证明记忆后端已加载。

## 本地可用，远程或手机不可用

先确认电脑和手机访问的是同一个酒馆实例。检查反向代理是否将 `/api/plugins/...` 转发到酒馆，并结合失败请求和启动日志判断，不要先认定是 Safari 问题，也不要为了排障关闭安全设置。

当前没有“后端连接检查”按钮。可在同一已登录的酒馆地址后加 `/api/plugins/st-bainiaodata/v1/health` 查看健康路由；直接访问可能受宿主登录保护，失败本身不是唯一证据。有浏览器网络工具时，可查看失败请求的路径和状态码。普通用户无需先学会编写控制台脚本。

## 尚未记录、读取中或待核对

“尚未开始记录 / 尚未建立聊天 ID”时，先打开实际聊天。新聊天可正常对话，由摘要逐步建立记忆；旧聊天可按需要到记忆管理手动补齐。空聊天还没有可保存的记录可以是正常状态。

“读取中”表示正在加载现有记录。若一直不结束或反复失败，先看完整提示和诊断，不要无限等待或反复删除重构。旧档突然全空或出现 `needsReview` 时，先在记忆管理点“刷新状态”并检查诊断。

批量删尾后待核对，也先点“刷新状态”；保留前缀核验通过时可恢复。普通打开不会自动做这项恢复，也不保证任意中间删除适用。没有改善时请保留证据再求助。

## 模型错误或空回

失败地址若是模型端点，核对模型 API 地址、模型名和所选预设，保留完整错误。空回复与存储后端 404 是不同问题，不能根据一个状态码就宣称已找到原因。正常召回到零条记忆也不等于模型空回或历史记忆为空。

## 求助时提供什么

提供插件版本、酒馆类型（原生或 Luker）、操作步骤、完整提示、“记忆管理 → 详细诊断”中的诊断 JSON，以及失败请求路径和状态码；启动日志按需补充。

诊断可能包含正文，转发前先检查并打码。路径、文件名可以打码但保留目录结构；不要发送 API key、`Authorization`、`Cookie`、整份配置、整段聊天或隐私人物截图。尽量保留错误文字和操作顺序，便于区分安装、模型请求和当前聊天记录问题。
