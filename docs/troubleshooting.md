# 千千结排障手册

先记下完整提示、操作顺序和失败发生的时间。不要因为某一项读取或安装失败就先删记忆；“完全重构”会清除当前聊天的千千结记录和前情，再从正文重建，正文保留。它不是修复安装或连接问题的通用按钮。

## 摘要里缺正文或很多楼没有摘要

先检查“设置 → 通用设置 → 提示词与包裹符 → 包裹符”中的“保留包裹符”。默认保留名称是 `content`。清洗时，匹配到的完整成对标签会去掉标签外壳、留下内部内容；普通文字会保留。其他完整成对标签中的普通文字可能被排除。

例如，正文全包在 `<story>…</story>` 中，而保留名单仍是 `content`，清洗后这楼可能没有正文。普通“清洗包裹符”标签名不会覆盖保留名单；但其中的字面规则 `[[...]]` 会删除成对符号之间的内容，所以也要检查它是否圈住正文。未闭合标签不会一概导致正文丢失。

确认实际正文使用的标签后，把需要保留的标签名填入“保留包裹符”。然后回到“千结”或“设置 → 记忆管理”刷新状态，查看界面给出的后续处理提示。保存诊断和失败楼号；先不要盲目完全重构。

## 后端没加载或出现 404

千千结是浏览器里的前端扩展，白鳥数据 ST-BaiNiaoData 是保存记忆的服务端插件，模型 API 又是另一项配置。三者要分别检查。

- 后端仓库是 [ST-BaiNiaoData](https://github.com/atonal519/ST-BaiNiaoData)。Luker 可使用后台的服务端插件管理安装。原生酒馆默认路径应为实际酒馆根目录下的 `plugins/ST-BaiNiaoData/index.mjs`；解压时不要多套一层同名文件夹。不要把后端装进千千结前端所在的 `public/scripts/extensions/third-party`。
- 在实际运行的酒馆根目录 `config.yaml` 检查已有的 `enableServerPlugins` 是否为 `true`。如果该键已经存在，修改原值，不要再添加一个同名键。默认 `serverPluginsPath` 是 `./plugins`；如果改过，就按当前配置路径安装。`enableServerPluginsAutoUpdate` 只控制自动更新，不决定插件是否加载。
- 安装后端或改配置后，需要完整重启酒馆服务，再刷新网页。只刷新网页、重开面板或切换千千结开关都不能加载服务端插件。若仍失败，查酒馆启动日志中的插件加载错误。

按失败地址区分：

| 失败请求 | 先检查什么 |
| --- | --- |
| `/api/plugins/st-bainiaodata/v1/health` 找不到 | 后端目录、服务端插件启用配置、是否完整重启、启动日志；远程访问再查代理路由。 |
| `GET /api/plugins/st-bainiaodata/v1/records/.../ID` 返回 `not_found` | 这条记录不存在。新档尚未记录，或还没有时间事项时缺少某条记录可能正常；旧档突然全空或持续失败则继续核对。 |
| 模型服务地址返回 404 | 模型 API 地址、模型名和当前预设；保留完整错误。 |

空集合查询会正常返回 `200` 和 `[]`。千千结通用后端错误只保留状态码，不会解析错误响应正文，因此单独一个“HTTP 404”不能证明原因；也不能把所有记录 404 都当成正常。模型“测试连接”成功只说明那次模型测试成功，不代表记忆后端已加载。

当前没有“后端连接检查”按钮。可在同一已登录的酒馆地址访问 `/api/plugins/st-bainiaodata/v1/health`，或在浏览器网络工具里查看失败请求的路径和状态码。直接访问可能受宿主登录保护；访问失败本身不是唯一证据。普通用户不需要先学会编写控制台脚本。

如果电脑能用、远程或手机不能用，先确认两边访问的是同一个酒馆实例；再结合失败请求检查反向代理是否把 `/api/plugins/...` 转发到酒馆。不要先认定是浏览器问题，也不要为了排障关闭安全设置。

## “尚未记录”“读取中”“准备中”或“待核对”

- “尚未开始记录 / 尚未建立聊天 ID”：先打开实际聊天。新聊天正常对话即可逐步建立记忆；旧聊天可按需要到记忆管理手动补齐。空聊天还没有可保存的记录是正常状态。
- “读取中”：正在加载已有记录。若一直不结束或反复失败，查看完整提示、失败请求和详细诊断；不要无限等待或反复删除重构。
- “准备中”或“待核对”：在健康条和“记忆管理 → 详细诊断”查看当前阶段。刷新状态会读取、核对现状，不调用模型，也不会自动恢复已暂停的历史任务。删尾后待核对，可先刷新状态；是否能恢复取决于界面核验结果，不适用于任意中间删除。

没有改善时，保留诊断、失败楼号和操作顺序再求助。不要连续启动同一历史任务，也不要先删除记录。

## 页面等待很久、模型请求失败或空回

后端记录读取超时，先看失败请求路径、状态码和“记忆管理 → 详细诊断”中的阶段与耗时。模型 API 失败则核对所选预设、模型地址和模型端错误。模型端 404 与后端记录读取失败是两类问题。

缓存读取、首次冷读取和酒馆整页卡顿也不是同一种情况。保留发生时间、聊天规模、完整提示和失败请求；页面恢复后可以按提示再试，但一次重试成功不能证明冷读取超时或整页卡顿已经根治。

召回看起来为空时，打开对应楼的“最近召回”或召回回执，确认本轮实际选入的材料。正常召回可以得到 0 条，不等于历史摘要或人物档案为空；年表里的事件很多，也不代表它们每轮都会全部注入。模型没有返回正文时，再按模型请求错误排查。

## 存储空间与清理

打开“设置 → 记忆设置 → 存储管理”，点“刷新统计”查看当前聊天的记录占用和可清理旧版本数量。统计只读检查；清理前还会要求确认。

“清理旧版本”只删除当前版本已不再引用的千千结后台基础文件。它不会删除当前摘要、人物状态、千人人物资料、刻度或聊天正文。清理的旧后台版本不能恢复。自动清理默认关闭；开启后，每新增 10 个稳定 AI 楼检查一次，且达到无引用旧文件 100 条或约 8 MiB 才会清理，任务忙时会顺延。

## 求助时提供什么

请尽量提供插件版本、酒馆类型（原生或 Luker）、操作步骤、完整提示、失败时间、详细诊断 JSON，以及失败请求路径和状态码。启动日志可按需补充。

“复制完整诊断”可能包含聊天正文，转发前请自己检查并打码。安全诊断不含完整楼层正文，但可能包含摘要、剧情细节和编号，转发前也请检查。不要发送 API key、`Authorization`、`Cookie`、整份配置、整段聊天或人物隐私截图。路径和文件名可以打码，但尽量保留目录结构、错误文字和操作顺序，方便区分安装、后端读取和模型请求问题。
